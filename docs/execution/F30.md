# Checkpoint F30 — hotfix de generación de códigos

## Resultado

Se corrigió la RPC `create_wallet_observer_pairing`. Su `UPDATE` usaba referencias sin calificar
para `restaurant_id` y `receiver_account_id`; PostgreSQL las trataba como ambiguas por las columnas
implícitas de `RETURNS TABLE`. El alias `pairing` elimina la ambigüedad.

La migración `20260920160000_fix_wallet_observer_pairing_ambiguity.sql` quedó aplicada y registrada
en Supabase producción. La prueba transaccional con una cuenta autorizada confirmó identificador,
código de ocho caracteres hexadecimales y expiración futura; se hizo `ROLLBACK`, sin datos de prueba.
