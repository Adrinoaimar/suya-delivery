# Checkpoint F7 — Ubicación, mapas y alertas

## Resultado

- Checkout solicita GPS solo por acción explícita. La dirección privada nunca se envía a Nominatim
  ni a otro geocodificador público.
- Cliente fija coordenadas mediante RPC idempotente. Un pedido sin ambos puntos verificados no puede
  asignarse a un repartidor.
- Mapas usan Leaflet y tiles OpenStreetMap configurables, atribución visible y estado accesible sin
  conexión. La línea entre puntos se presenta como referencia, no como ruta vial calculada.
- Repartidor publica GPS real mediante RPC: identidad y hora provienen del servidor, pedido debe ser
  propio y activo, coordenadas se validan y la frecuencia queda limitada a una muestra cada 8 s.
- Cliente participante recibe última posición y nuevas muestras por Realtime con RLS.
- Incidentes y SOS son idempotentes, persistentes y limitados a riders verificados. SOS notifica al
  rider y responsables del restaurante; el rider puede marcarse a salvo mediante RPC autorizada.
- Inserción directa de ubicaciones e incidentes quedó revocada. Coordenadas parciales, descripciones
  inválidas, pedidos ajenos y GPS simulado se rechazan.
- Enlace público de seguimiento permanece deshabilitado hasta contar con token criptográfico, TTL,
  revocación y rate limit server-side.

## Límites honestos

- Pagos digitales siguen deshabilitados. Efectivo es el único medio activo.
- Postgres Changes con frecuencia limitada sirve al MVP. Broadcast privado será necesario al crecer.
- OpenStreetMap muestra puntos; todavía no existe motor de rutas ni ETA vial.
