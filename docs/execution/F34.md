# F34 — Corrección de login Android y OTA por rol

Fecha: 2026-09-21 (`America/Lima`)

## Causa confirmada

`SuyaSecureStoragePlugin` generaba un IV AES-GCM manual y se lo entregaba a una clave
Android Keystore. En algunos dispositivos/API el proveedor rechaza ese parámetro al
guardar la sesión de Supabase, aunque las credenciales sean correctas. La rotación del
alias a v2 por sí sola no corregía la causa.

## Corrección

- `SecureAuthCipher` deja que Android Keystore genere el IV y persiste IV+ciphertext.
- Se mantiene AES-GCM, clave no exportable, namespace v2 y rechazo cerrado; no hay
  fallback en texto plano.
- Se añadió una prueba instrumentada de cifrado/descifrado y regresión del mensaje
  seguro en `authStore`.
- La OTA ahora usa manifiestos separados para `customer`, `rider`, `backoffice`,
  `walletobserver` y `unified`; cada APK valida rol, origen, ruta, checksum y firma.
  El manifiesto raíz permanece como compatibilidad para APKs antiguas de Cliente.

## Pendiente / límites

- Esta máquina no tiene JDK ni `adb`; no se declara compilación o instalación Android
  local. CI queda configurado para `:app:connectedDebugAndroidTest` en API 35.
- No se publicó producción ni se modificó Supabase. La nueva OTA solo queda disponible
  después de una publicación protegida; el cambio Java requiere una APK correctiva una
  vez. Las actualizaciones web posteriores sí pueden llegar por OTA.
