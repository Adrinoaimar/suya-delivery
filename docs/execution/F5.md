# Checkpoint F5 — Catálogo Supabase y Andá Paya

## Resultado

- `SupabaseStoreService` lee categorías, restaurantes y productos públicos sujetos a RLS.
- El router carga el mock solo en desarrollo/pruebas; el build `VITE_BACKEND=supabase` no contiene
  `MockStoreService` ni su marca `DEMO DATA`.
- Categorías, búsquedas, ficha y menú consumen el servicio asíncrono, no JSON directo.
- Metadatos comerciales distinguen valores desconocidos: sin horario, distancia o reseñas no se
  muestran cifras inventadas. `accepting_orders` controla la operación.
- La carta de Andá Paya quedó trazada en 58 productos con UUID estables y seed idempotente.
- Tema confirmado: negro, rojo y blanco. El SVG inventado no se usa en el seed; el intento de
  extracción se rechazó porque no produjo transparencia real.
- Bebidas sin precio y datos comerciales ausentes no se publican.

## Evidencia local

- Typecheck y lint: pasan.
- 13 archivos / 70 pruebas frontend pasan.
- 13 pruebas focalizadas de adaptador/metadatos pasan; Cline/Kimi K3 xhigh aportó 10 pruebas del
  adaptador antes de agotar el límite de 300 segundos.
- Build productivo simulado customer: catálogo mock ausente; mocks de pedidos/mapa siguen detectados
  y pertenecen a los checkpoints siguientes.
- GitHub CI aprobó migraciones, seed, 50 pgTAP y `db lint`:
  [run 32346224149](https://github.com/Adrinoaimar/suya-delivery/actions/runs/32346224149).
- El primer intento detectó una firma pgTAP incorrecta; se corrigió mediante inspección exacta de
  `pg_constraint` antes del run aprobado.

## Gate deliberado

Andá Paya queda visible pero `accepting_orders=false`: faltan horario, dirección/coordenadas,
teléfono y política real de delivery. Activar pedidos con ceros sería información comercial falsa.
