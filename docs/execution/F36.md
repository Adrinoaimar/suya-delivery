# F36 — Auditoría Supabase y acceso de negocios

Fecha: 24 de septiembre de 2026 (`America/Lima`)

## Resultado

- Se validó lectura directa de la base productiva con `supabase db query --linked` y listado de Edge
  Functions. No hay herramientas Supabase MCP en este runtime; no se alteraron filas, esquema, ledger,
  secretos ni cuentas productivas. No se usó staging.
- Catálogo de seguridad: 28/28 tablas `public` tienen RLS; no hay políticas cliente abiertas con
  `true`. Persisten dos tablas `private` sin RLS, aunque no tienen grants de lectura cliente.
  Ocho RPC pensadas para usuarios autenticados aceptan `anon`; `get_order_codes` también carecía de
  guardia para identidad nula.
- `supabase db lint --linked` encontró errores en `record_cash_sale` y `add_cash_adjustment` por
  referencias ambiguas a `session_id`. Se prepararon migraciones y pgTAP para cerrar estos hallazgos.
- La migración histórica de imágenes no está en el ledger remoto. Comparación directa y de solo
  lectura: sus 58 mapeos de un catálogo y 29 del otro ya coinciden con producción. No se reparó el
  ledger hasta superar los gates de despliegue y base de datos.
- Las foreign keys sin índice que encontró el catálogo (25 entre esquema de app y administrado) son
  un backlog para priorizar con consultas y tráfico, no una instrucción para crear índices a ciegas.

## Acceso comercial

- Un usuario propietario está activo y confirmado; su contraseña no se conoce. No se envió reset.
- Dos perfiles nuevos siguen sin correo, usuario propietario ni cuenta Auth confirmada.
- Solo `route-driving` aparece desplegada; falta `invite-restaurant-owner`.
- Cloudflare Email Routing está `unconfigured`, sin destinos ni reglas. El dominio no publica MX.
  El conector permite lectura de zona, pero no escritura. Sin una bandeja receptora y permisos de
  escritura no pueden crearse alias que reciban invitaciones. No se inventaron buzones ni cuentas.

## Verificación

- Pasaron antes de cerrar este checkpoint: `npm run typecheck`, `npm run lint`,
  `npm run security:secrets`, `npm test` (77 archivos, 393 pruebas), `npm run build` y
  `git diff --check`.
- Falló `npm run verify:production`: faltan variables de Supabase/mapas/analítica y el build local
  contiene servicios `Mock*`.
- `npm run db:test` no pudo conectarse al PostgreSQL local (`127.0.0.1:54322`); Docker no está
  disponible. El lint remoto sigue mostrando los dos errores de caja.
- APK local disponible: `1.7`/`versionCode 8`; no se generó otra APK. La verificación de firma/APK
  completa sigue bloqueada porque faltan `aapt2` y `apksigner` en el SDK instalado.
- No se lanzó emulador: la memoria disponible rondaba 3.2 GiB y el swap estaba agotado.

## Bloqueos y continuidad

1. Conseguir una bandeja real y permisos de escritura de correo antes de crear direcciones en el
   dominio; confirmar contacto comercial para los perfiles nuevos.
2. Conciliar de forma revisable la entrada histórica en el ledger; después ejecutar pgTAP/db lint en
   un entorno local o CI y repetir `verify:production`.
3. Aplicar las dos migraciones solo tras pasar preflight. Luego desplegar la función de invitación,
   completar verificación de correo y probar login en emulador/dispositivo.
4. No publicar commits directamente mientras el commit local Android anterior siga pendiente: sus
   rutas `scripts/**` activan el workflow de Cloudflare Pages al hacer push a `main`.

La auditoría completa está en `docs/reports/supabase-audit-2026-09-24.md`.
