# F35 — Preparación de firma y distribución Android

Fecha: 2026-09-23 (`America/Lima`)

## Objetivo y corrección

Preparar la actualización de Cliente, Rider, Backoffice y Wallet Observer sin presentar APKs
debug o unsigned como releases. `docs/setup/android-release-signing.md` documentaba variables de
firma que `android/app/build.gradle` no utilizaba. Gradle ahora conecta esas cuatro variables,
rechaza configuración parcial e informa cuáles faltan; sin ellas conserva el build unsigned.

## Evidencia

- `npm run typecheck`: PASS.
- `npm run lint`: PASS.
- `npm run security:secrets`: PASS; 823 archivos Git revisados.
- `npm test`: PASS; 85 archivos, 411 pruebas (incluidas dos pruebas estáticas de la configuración
  de firma; no equivalen a compilar Gradle).
- `npm run build`: PASS con proyecto, clave pública y URLs sintéticas; genera customer, rider y
  backoffice, y `verify:production` acepta 700 archivos sin mocks ni secretos. No es staging real.
- Se localizaron Java, Android SDK, `adb`, `apksigner` y dos AVD ya instalados fuera del `PATH`.
  `:app:tasks` pasó; Gradle rechazó una firma parcial con los tres nombres faltantes.
- Se localizó un keystore ignorado por Git y se restringió su lectura al propietario. `keytool`
  confirmó que contiene el alias original. `apksigner` confirmó que las cuatro APK release
  1.6/code 7 tienen el mismo certificado. La firma Gradle de una APK Cliente 1.7/code 8 con
  backend sintético pasó y `apksigner` confirmó el mismo certificado.
- En AVD API 35: instalación code 7, actualización `adb install -r` a code 8 y apertura de la
  actividad principal: PASS. No se observó excepción fatal del proceso. El paquete sintético
  se retiró del AVD y el emulador se detuvo; el artefacto sintético se eliminó tras verificarlo.
- GitHub Actions ahora tiene URL y project ref reales de Supabase staging más su clave pública
  en Secrets. Staging sigue sin migraciones ni Edge Functions. Faltan routing URL operativa y
  tres URLs web de staging; no deben sustituirse por destinos ficticios.
- [Segundo Android CI](https://github.com/Adrinoaimar/suya-delivery/actions/runs/35939987627):
  `BLOCKED` en `verify:mobile-qa-env` solo por `VITE_ROUTING_URL`,
  `VITE_CUSTOMER_APP_URL`, `VITE_RIDER_APP_URL` y `VITE_BACKOFFICE_APP_URL` ausentes.
- [Android CI del commit `1091125`](https://github.com/Adrinoaimar/suya-delivery/actions/runs/35937323674):
  `BLOCKED` en `verify:mobile-qa-env`, antes de compilar. Faltan URL, project ref y publishable
  key de Supabase staging, routing URL y URLs de customer/rider/backoffice staging. Por tanto,
  no hay artefactos ni prueba de emulador de este commit.

## Bloqueos para distribuir

1. Custodiar la clave original en un gestor seguro y sanear su contraseña sin cambiar el par de
   claves ni el certificado. No incluir clave ni contraseña en Git, CI o documentación pública.
2. Aplicar migraciones y Edge Functions a staging; publicar URLs web aisladas y funcionales.
3. Ejecutar Android CI y pruebas de login, pedidos, instalación/actualización y regresión por
   rol contra staging. La prueba de actualización Cliente sintética no valida estos flujos.
4. Tras aprobar QA, compilar los cuatro roles con backend autorizado, firmar, verificar paquetes,
   versión y certificados, y solo entonces empaquetar las APK para distribución.

Estado: **NO APTO PARA DISTRIBUCIÓN**. La APK firmada fue solo una prueba sintética y se eliminó;
no se envió ninguna APK ni se desplegó producción.
