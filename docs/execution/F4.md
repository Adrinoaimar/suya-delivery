# Checkpoint F4 — Supabase Auth y roles

## Resultado

- Cliente Supabase único; sesión persistente y refresco automático.
- Registro de clientes e inicio/cierre de sesión por correo y contraseña.
- Trigger Auth crea `profiles` sin aceptar roles desde `user_metadata`.
- Capacidades derivadas de fuentes protegidas: rider verificado/no suspendido, membresía activa y
  `app_metadata.role=platform_admin`.
- Cliente protege checkout, pedidos y perfil; rider exige capacidad rider; operaciones exige
  exclusivamente platform admin.
- Pedidos no se hidratan antes de Auth y se limpian al cambiar/cerrar cuenta.
- Respuestas async de identidad/pedidos llevan generación para impedir que una cuenta anterior
  sobrescriba la sesión actual; perfil y checkout leen `public.profiles`, no datos personales locales.
- URL Supabase debe coincidir con `VITE_EXPECTED_SUPABASE_PROJECT_REF`; evita conectar otro proyecto.
