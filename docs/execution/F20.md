# F20 — APKs operativos separados

Fecha: 12 de septiembre de 2026 (`America/Lima`).

## Objetivo

Entregar una aplicación Android instalable para repartidores y otra para backoffice, manteniendo los
mismos flujos web protegidos, backend Supabase, permisos GPS y reglas de acceso.

## Resultado

- `npm run build:mobile:roles` compila `rider` y `backoffice` y sincroniza cada bundle con Capacitor.
- Rider usa `com.suya.rider` y `Suya Repartidor`.
- Backoffice usa `com.suya.backoffice` y `Suya Backoffice`.
- La configuración nativa y el callback OAuth se parametrizan por rol; el APK unificado
  `com.suya.app` conserva sus valores por defecto.
- GitHub Actions publicó dos APKs debug en el PR #35.

## Verificación

- `npm run typecheck` pasó.
- `npm run lint` pasó.
- `npm test` pasó: 36 archivos y 190 pruebas.
- `npm run security:secrets` pasó.
- Bundles `rider` y `backoffice` aislados, y `cap sync android`, pasaron con configuración sintética.
- El job Android `debug` pasó en CI y publicó ambos artefactos.

El job general de Supabase local falló por conflicto externo del puerto `54322`; no corresponde al
cambio móvil y las pruebas locales sí pasaron.

## Pendientes

Android release. Estos artefactos debug son solo para pruebas internas.
